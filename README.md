# Личный ML Tutor в Telegram

Бот для последовательного развития навыков ML Engineer до middle+/senior: приглашает на занятия по расписанию, объясняет материал, отвечает на вопросы и проверяет понимание. Интерфейс и обучение на русском языке.

## Возможности

- 30 тем, 87 разделов-уроков по исходному списку hard и soft skills. Полный [учебный план](docs/curriculum.md).
- Несколько приглашений в день: по умолчанию **10:00, 14:00, 19:00, Europe/Moscow**. Часовой пояс, время и пауза настраиваются в боте.
- В начале урока: «Не знаю — объясни» или «Знаю — сразу тест».
- Понятный текст с примерами; затем свободные вопросы к LLM с контекстом текущего урока.
- 3–5 открытых вопросов по одному. Оценка каждого ответа: 0 — неверно, 1 — частично, 2 — полно. Для прохождения нужно **не менее 80%** суммы: например, 7 из 8 для четырёх вопросов.
- Подробный разбор после всего теста. Можно разобрать тему заново, повторить тест или отложить на 24 часа.
- Каталог всех тем и разделов с тремя статусами: «Пройдена», «Не пройдена», «Провалено тестирование». Любой раздел доступен вручную, независимо от порядка.
- SQLite хранит расписание, текущий этап, материал, последние 12 пар вопросов/ответов, ответы теста, результаты и историю завершённых попыток.
- Доступ только владельцу в личном чате. Посторонние пользователи и группы игнорируются.
- Служебные сообщения (меню, страницы каталога, расписание, приглашения, уведомления о генерации) заменяются: после отправки нового экрана предыдущие удаляются. Материалы уроков, вопросы, ответы и результаты тестов остаются в чате. Список служебных сообщений сохраняется после перезапуска. Старые сообщения, отправленные до обновления, автоматически не известны боту; нажатая старая страница меню будет убрана при переходе. Если Telegram запрещает удаление (например, сообщение старше 48 часов), бот продолжит работу без удаления этого сообщения.

## Быстрый запуск

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

1. Создайте Telegram-бота через [@BotFather](https://t.me/BotFather) и получите токен.
2. Подготовьте свой числовой Telegram user ID. Это именно ID пользователя, не `@username`.
3. Получите ключ LLM API и выберите модель, поддерживающую Chat Completions и JSON Schema. Конкретная модель не зашита в код.
4. Установите зависимости и создайте локальный файл настроек:

```powershell
uv sync --locked
Copy-Item .env.example .env
```

Заполните в `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_OWNER_ID=ваш_числовой_id
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=ключ_api
LLM_MODEL=идентификатор_выбранной_модели
```

Затем:

```powershell
uv run --locked python main.py
```

Откройте бота в Telegram и нажмите **Start / `/start`**. До первого обращения владельца рассылка не активируется. Telegram не позволяет боту первым начать переписку с человеком.

Токены не отправляйте в переписку и не коммитьте: `.env` исключён из Git и Docker-контекста. Текст уроков, ваши вопросы и ответы теста передаются выбранному LLM-провайдеру. Локальная база содержит историю обучения в открытом виде; храните её в своём окружении.

## Настройка LLM

Адаптер отправляет запросы на `{LLM_BASE_URL}/chat/completions` через HTTP. Использует `model`, `messages`, `max_completion_tokens` и `response_format`. Нужен провайдер с совместимым контрактом; совместимость со всеми API не подразумевается.

`LLM_JSON_MODE`:

| Значение | Формат |
| --- | --- |
| `schema` | Строгий `json_schema`, основной режим |
| `json` | `json_object`, если строгая схема недоступна |
| `prompt` | Только инструкция вернуть JSON, для провайдеров без `response_format` |

Во всех режимах ответ проверяется Pydantic: структура, число вопросов, длины текста, диапазон баллов. Неверные ответы модели и временные сетевые сбои повторяются максимум три раза. Ошибки авторизации показываются без тела ответа API. При сбое проверки ответы ученика сохраняются, появляется «Повторить проверку».

Порог прохождения считает код, LLM отвечает за оценку по приватным критериям каждого вопроса. Промпт запрещает следовать инструкциям внутри ответов ученика; это снижает риск манипуляции оценкой, но не гарантирует безошибочное оценивание. Короткий тест не является подтверждением уровня senior: нужны самостоятельные практические проекты.

## Команды и поведение

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Помощь и основные кнопки; урок не сбрасывается |
| `/lesson` | Начать следующий доступный урок или восстановить текущий |
| `/topics` | Темы → разделы → выбор любого урока |
| `/progress` | Количество пройденных и проваленных разделов |
| `/schedule` | Расписание, изменение времени, пауза |
| `/schedule Europe/Moscow 09:00,13:30,19:00` | Сохранить пояс и 1–6 времён |
| `/cancel` | Отменить ввод расписания, сохранив урок |

Статус раздела отражает **последний завершённый тест**. Начало повторения не стирает результат; новая неуспешная попытка меняет статус с «Пройдена» на «Провалено тестирование». История предыдущих попыток остаётся в базе. Статус темы — «Пройдена», только если пройдены все разделы; при наличии проваленного раздела — «Провалено тестирование».

Автовыбор идёт по учебному плану и пропускает пройденные и отложенные разделы. «Следующий урок» после провала откладывает текущую тему на 24 часа. Ручной выбор позволяет вернуться раньше. Если есть незавершённый урок, замена другим требует нажатия «Начать выбранный». Она сбрасывает только незавершённую сессию, а не результаты завершённых тестов.

Приглашение не прерывает текущий урок и не вызывает LLM до вашего действия. Во время генерации второй запрос отклоняется с просьбой повторить после ответа. Основные действия — кнопками, ответы и уточнения — текстом. Вложения и голосовые сообщения пока не поддерживаются.

## Расписание и постоянная работа

Бот должен постоянно работать на включённом компьютере или сервере. Планировщик проверяет время каждые 30 секунд; допускает задержку приглашения до 10 минут. После долгого простоя старые приглашения не накапливаются. Повторный час при переходе с летнего времени не создаёт вторую отправку; несуществующий местный час пропускается.

Отправленные слоты хранятся в SQLite. Запись создаётся **до** отправки, чтобы перезапуск не дублировал приглашения. Компромисс: при аварийном завершении между записью и отправкой или неоднозначной сетевой ошибке одно приглашение может быть пропущено. Подтверждённый Telegram rate limit повторяется с учётом `retry_after` в пределах окна; блокировка бота ставит приглашения на паузу. После разблокировки включите их в расписании.

Значения `.env` для времени используются при первой регистрации. После этого приоритет имеют сохранённые настройки из Telegram.

### Docker

```sh
docker compose up -d --build
docker compose logs -f tutor
```

Контейнер работает от непривилегированного пользователя. Прогресс хранится в именованном томе `tutor-data`, перезапуск его сохраняет. Не используйте `docker compose down -v`, если хотите сохранить данные. Запускайте **один экземпляр** бота на токен и базу; горизонтальное масштабирование этой личной версии не предусмотрено. Long polling не требует публичного порта или webhook.

Для резервного копирования остановите бота и скопируйте каталог данных / Docker-том целиком. Не копируйте только основной SQLite-файл при работающем процессе: используется WAL. Локальный путь по умолчанию — `data/tutor.sqlite3`.

## Разработка и проверка

```powershell
uv run --locked pytest -q
uv run --locked ruff check .
uv run --locked ruff format --check .
```

Тесты используют подменённые Telegram и LLM API: проверяют полный сценарий урока, авторизацию, старые кнопки, оценивание, повторения, восстановление SQLite, сбои LLM, часовые пояса и защиту от повторных приглашений. Живые интеграции требуют настоящих ключей.

После обновления зависимостей обновите Docker-список:

```sh
uv export --locked --no-dev --no-emit-project --format requirements-txt --output-file requirements.txt
```

Структура:

- `tutor/curriculum.py` — учебный план со стабильными ID; существующие ID нельзя перенумеровывать без миграции прогресса.
- `tutor/engine.py` — управляемые этапы LLM-агента: знакомство → объяснение/вопросы → тест → проверка → результат.
- `tutor/llm.py` — промпты, схемы, проверка и HTTP-адаптер.
- `tutor/storage.py` — SQLite и атомарное сохранение результатов.
- `tutor/scheduler.py` — ежедневные приглашения с часовыми поясами.
- `tutor/bot.py` — Telegram-интерфейс, доступ владельца, блокировка параллельных действий.

Сценарий контролирует приложение; LLM не имеет доступа к базе, выполнению кода или произвольным внешним инструментам.

Документация API, использованная при разработке: [aiogram Dispatcher](https://docs.aiogram.dev/en/dev-3.x/dispatcher/dispatcher.html), [Structured Outputs](https://openai.com/index/introducing-structured-outputs-in-the-api/).
